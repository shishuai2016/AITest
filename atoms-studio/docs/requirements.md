## 1. 背景与目标

### 1.1 任务背景

Atoms（https://atoms.dev/）代表了一类新的产品形态：用户用自然语言描述想法，智能体理解需求、规划界面并生成一个可以直接运行的网页应用。本次任务要求在有限时间与资源内，做出一个具备真实交互、真实数据持久化、可在线访问的 Atoms-like Demo，并至少覆盖一个延展能力（文档 / PPT / 报告）。

### 1.2 产品目标

Atoms Studio 的目标不是做一个「代码片段生成器」，而是交付一个**从想法到可分享产品**的完整闭环：

1. **一句话生成**：用户输入中文想法，智能体完成产品命名、定位、功能规划与代码生成。
2. **真实可用**：生成的应用打开即可操作，具备真实表单、增删改查、筛选、空状态与错误反馈，而不是静态截图。
3. **真实持久化**：项目、版本、消息、交付物写入服务端 SQLite；生成的应用通过注入的 `atomsStore` 把业务数据写入服务端，刷新或换设备仍然存在。
4. **可迭代、可回溯**：用户可以继续用自然语言修改应用，每次修改产生新版本，可预览、恢复历史版本。
5. **可分享、可交付**：每个应用生成公开分享链接；同时自动产出 PRD、7 页演示 PPT（可导出 .pptx）和自动验收报告。

### 1.3 非目标（本期不做）

- 注册、登录与多租户权限体系（Demo 无需注册）。
- 将应用部署到用户自己的域名/服务器；本期提供平台内预览与分享页。
- 真实的多人实时协作、评论、团队空间。
- 复杂的计费系统；仅保留演示额度与日志。
- 生产级代码安全审计（生成代码在受控 Demo 环境中运行）。

## 2. 目标用户与场景

| 用户 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 独立开发者 / 产品经理 | 在评审前快速做出一个可点击的原型 | 快、能改、能分享 |
| 创业者 / 业务负责人 | 验证一个内部工具或小产品想法 | 真实可用、能演示、有文档 |
| 设计师 / 运营 | 快速搭建活动页、看板、收集表 | 视觉完成度、移动端体验 |
| 学生 / 学习者 | 用 AI 完成课程项目或作品集 | 无需配置环境、数据不丢 |

产品不需要注册。首次访问时由浏览器 Cookie 标识匿名工作区，用户可以立即开始创作。

## 3. 核心体验

### 3.1 首次生成

```
打开首页 → 输入想法 / 选择模板 → 智能体流式工作
→ 规划产品（名称、定位、功能、实现步骤）
→ 生成 HTML / CSS / JS
→ 自动校验 + 修复
→ 渲染预览 + 服务端持久化检查
→ 发布 v1 + 生成分享链接
```

生成过程中，对话区与预览区同步展示：当前步骤、实时代码输出、已用时长、产品方案标签、警告与修复信息。用户不需要盯着空白等待。

### 3.2 迭代

- 用户在对话框继续输入修改需求，例如「换成深色主题」「加一个搜索框」「优化手机端布局」。
- 智能体基于当前版本完整文件进行修改，输出新的完整版本，而不是不可用的 diff。
- 每次迭代产生新版本号；旧版本保留，可以预览、恢复。
- 版本列表展示摘要、用户需求、模型、Token 用量和时间。

### 3.3 分享与使用

- 工作室顶部「分享」打开分享弹窗，可复制公开链接、开关公开状态。
- 分享页 `/s/:slug` 以全屏方式呈现生成的应用，右下角保留一个轻量品牌标识，可回到工作室。
- 公开链接不需要登录；生成的应用数据仍通过服务端持久化。
- 支持下载当前版本的**单文件 HTML**（CSS/JS 内联），可离线打开。

### 3.4 交付物

每个版本都可以生成：

1. **产品需求文档（PRD）**：基于当前版本真实功能反向生成，包含目标用户、核心流程、功能优先级表、数据与持久化、验收标准、后续迭代建议；支持 Markdown 下载。
2. **演示幻灯片**：7 页发布会节奏的 Deck，自动匹配应用气质与主色，包含封面、问题、洞察、产品、体验、技术、收尾，附演讲备注；支持在线翻页、全屏演示、导出 .pptx。
3. **自动验收报告**：每次生成后自动运行，检查预览可访问性、运行时代码注入、JavaScript 语法、本地资源引用、离线可用性、数据持久化、响应式基础、交互元素、内容完整性等，输出评分与逐项明细。

## 4. 功能需求

### 4.1 P0 功能

| 编号 | 功能 | 描述 | 验收标准 |
| --- | --- | --- | --- |
| F1 | 想法输入 | 首页提供大输入框、模板与灵感切换 | 少于 4 字有提示；⌘/Ctrl+Enter 提交 |
| F2 | 智能体规划 | 生成前输出产品名、定位、功能点、实现步骤、主色 | 规划结果在生成过程中可见；失败时可降级 |
| F3 | 流式生成 | 实时展示代码输出、步骤状态、耗时 | SSE 断线重连；刷新后仍能恢复任务状态 |
| F4 | 沙箱预览 | 生成完成后自动渲染可交互应用 | iframe 内可操作；桌面/平板/手机三种尺寸 |
| F5 | 服务端持久化 | 项目、版本、消息、交付物写入 SQLite | 重启服务后数据仍在；刷新页面不丢 |
| F6 | 应用数据持久化 | 生成应用通过 `atomsStore` 读写业务数据 | 刷新后生成应用中的任务/订单/打卡记录仍在 |
| F7 | 自然语言迭代 | 基于当前版本继续修改并生成新版本 | 旧功能不丢失；新需求生效 |
| F8 | 版本历史与恢复 | 查看历史版本、预览、恢复 | 恢复会创建新版本，不覆盖历史 |
| F9 | 分享页 | 公开链接全屏展示生成应用 | 未公开时显示未公开提示；可开关 |
| F10 | 单文件下载 | 将多文件应用内联为一个 HTML | 下载后可离线打开并保留交互 |
| F11 | 自动验收报告 | 每次生成后自动检查并评分 | 15 项检查可读；失败时明确标红 |
| F12 | PRD 生成 | 按当前版本生成需求文档 | 可在线阅读、复制、下载 .md |
| F13 | PPT 生成与导出 | 生成 7 页 Deck，可在线翻页、全屏、导出 PPTX | .pptx 可被 PowerPoint/Keynote 打开 |
| F14 | 精选示例 | 首页展示 3 个已完成的应用 | 可直接打开、迭代、查看交付物 |
| F15 | 无注册 | 首次访问即可使用 | 不需要登录；匿名工作区 |

### 4.2 P1 功能

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| F16 | 深浅色主题 | 工作室与首页支持切换，偏好保存在浏览器 |
| F17 | 重命名 / 删除 | 应用支持重命名；非示例项目可删除 |
| F18 | 缩略图 | 生成完成后用无头 Chrome 截图作为作品封面 |
| F19 | 移动端适配 | 首页、工作室、分享页在 390px 宽度可用 |
| F20 | 生成额度保护 | 每日演示生成上限，避免滥用与模型额度耗尽 |
| F21 | 降级生成 | 模型不可用/未配置时，用内置演示引擎保证流程可跑通 |

### 4.3 交互细节

- 首页：Hero + 输入卡片 + 精选作品 + 模板 + 交付物能力 + 工作原理 + 页脚。
- 工作室：左侧对话、右侧预览；顶部标签切换预览 / 代码 / 交付物 / 版本。
- 生成中：预览区覆盖实时进度面板；对话区保留可滚动的运行卡片。
- 代码页：文件树 + 行号代码 + 一键复制。
- 交付物页：三个卡片式入口，缺省时生成、已生成时可打开/下载。
- 弹窗：PRD 阅读、Deck 翻页、验收报告、分享设置、项目操作、重命名。
- 所有重要操作有 Toast 或内联反馈；不使用 `alert/confirm/prompt`。

## 5. 数据与持久化

### 5.1 平台数据

本地 SQLite（`data/atoms.db`，WAL 模式）保存：

- `projects`：应用元信息、当前版本、分享状态、匿名工作区。
- `versions`：每次生成/恢复的完整文件、摘要、模型、Token 用量、检查结果。
- `messages`：用户需求与智能体产出摘要、方案、检查摘要。
- `jobs`：生成任务、步骤、错误；用于刷新后恢复任务状态。
- `artifacts`：PRD、幻灯片、验收报告。
- `app_store`：生成应用通过 `atomsStore` 写入的业务数据（按项目 + key 隔离）。
- `llm_calls`：模型调用与 Token 用量，用于成本观察与额度保护。

### 5.2 生成应用数据

预览环境在页面 `<head>` 注入 `atomsStore` 运行时：

```js
await atomsStore.get('todos', []);
await atomsStore.set('todos', todos);
await atomsStore.del('todos');
await atomsStore.list();
```

运行时通过同源 `/api/apps/:projectId/store/:key` 访问服务端 SQLite；下载后的独立 HTML 自动回退到 localStorage。所有 key 做白名单校验，单条数据上限 64KB。

## 6. 非功能需求

| 维度 | 要求 | 实现说明 |
| --- | --- | --- |
| 性能 | 首页可交互 < 1s；生成 60–180s | 静态资源本地、生成流式展示、不阻塞页面 |
| 可靠性 | 生成失败可恢复，不丢历史版本 | 版本写入 SQLite；失败显示错误；旧版本仍在 |
| 可用性 | 无注册、移动端可用、深浅色 | Cookie 匿名工作区；390px 断点 |
| 可观测 | 能定位生成失败原因 | 任务步骤、错误信息、LLM 调用记录 |
| 成本 | 避免无限消耗模型额度 | 单任务并发上限、每日生成上限、Token 记录 |
| 安全 | 模型密钥只在服务端 | 前端不接触 ARK_API_KEY；预览同源 |
| 兼容 | 现代 Chrome / Safari / Edge | 原生 ES Modules、CSS 变量、内联 SVG |

## 7. 验收标准

本次 Demo 以以下标准验收：

- [x] 在线链接无需登录即可打开，首页、精选应用、工作室、分享页均可访问。
- [x] 输入一句中文想法，能够生成一个包含真实交互的网页应用，并自动进入预览。
- [x] 生成过程有可感知的步骤与流式输出，而不是长时间白屏。
- [x] 生成应用的业务数据刷新后仍然存在（服务端持久化）。
- [x] 平台的项目、消息、版本、交付物在服务重启后仍然存在。
- [x] 可以用自然语言继续修改，产生新版本，并恢复历史版本。
- [x] 每个应用有公开分享链接，分享页全屏展示应用。
- [x] 自动验收报告每次生成后自动产出，失败项可见。
- [x] PRD 可在线阅读、下载；Deck 可在线演示、导出 .pptx。
- [x] 首页/工作室在手机尺寸可用，支持深浅色。
- [x] 模型不可用时仍有降级路径，不出现完全不可用的空页面。

## 9. 风险与后续

### 9.1 已知限制

- 生成耗时受模型影响较大，复杂应用可能需要 1–3 分钟；已用流式输出降低等待焦虑。
- 模型额度有限（免费额度约 50 万 Token），已设置每日生成上限并记录用量。
- 公开链接使用 Cloudflare Quick Tunnel，属于演示级部署，不保证长期稳定。
- 无登录与权限体系，所有项目共享同一个匿名工作区；不适合真实多租户场景。
- 生成代码由模型编写，进入生产前需要人工审查与安全加固。

### 9.2 后续迭代

1. 用户体系与团队空间、项目级权限。
2. 真正的部署能力（自定义域名、CDN、环境变量）。
3. 生成代码的安全沙箱与依赖白名单。
4. 更多交付物：DOCX、PDF、可编辑的 PPT 模板。
5. 应用内数据建模：从真实数据库 schema 生成 CRUD。
6. 多人协作与评论、版本对比 diff。
